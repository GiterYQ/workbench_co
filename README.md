# 内容运营工作台

一个本地优先的内容运营工作台。它把任务、日程、内容选题、作品复盘、客户跟进、会议纪要、知识库和可复用流程放在一个入口中，并通过环境变量连接个人数据目录或飞书多维表格。

本仓库是**空数据公开版**：仓库中不包含真实公司资料、真实账号、真实客户、真实作品、真实评论、真实投资人、真实飞书地址或任何访问凭证。首次启动看到空状态是正常的，数据需要由使用者自己导入或录入。

## 这不是开箱即用成品

这个项目提供的是一套**可改造的基础骨架**，不是已经替你定义好岗位、行业、字段和流程的现成系统。不同职业需要管理的对象不同：内容运营关注作品和选题，项目经理关注项目和交付，销售关注客户和商机，研究人员关注资料和结论。工作台的模块、字段、分类、状态、视图和自动化，都应该围绕你的实际工作重新配置。

你可以把仓库交给 WorkBuddy（[下载/进入 WorkBuddy](https://www.codebuddy.cn/events/invite?inviteCode=t01jaexsv7t8czda)），让它先理解你的职业和工作方式，再修改工作台。第一次使用建议按这个顺序：

1. 说明你的职业、服务对象、日常工作、固定产出和常用工具；
2. 让 WorkBuddy 先检查现有页面、接口和空数据结构，提出需要保留、删除和新增的模块；
3. 确认字段、流程和权限后，再让它修改代码或数据；
4. 最后导入真实资料，并按需要连接飞书、知识库或其他系统。

可以直接复制这段提示词开始：

> 我是【职业/岗位】，主要处理【工作对象】，目标是【希望改善的结果】，目前使用【工具和数据来源】。请先阅读 README.md、docs/完整使用指南.md、public/、server.mjs 和 data/，不要创建模拟业务数据，也不要直接改文件。请先根据我的实际工作提出：需要保留或删除哪些页面、需要哪些字段和状态、哪些内容应该放本地/飞书/知识库、哪些步骤可以自动化，并列出修改清单；等我确认后再执行。

## 快速开始

环境要求：Node.js 18 或更高版本。

```bash
git clone https://github.com/GiterYQ/workbench_co.git
cd workbench_co
cp .env.example .env
npm start
```

浏览器打开：<http://127.0.0.1:8787>

检查代码：

```bash
npm run check
```

## 用 CodeBuddy 操作

可以在 [WorkBuddy 下载/进入页](https://www.codebuddy.cn/events/invite?inviteCode=t01jaexsv7t8czda) 中打开或导入本仓库，让 AI 按工作台的字段和接口协助维护。建议第一次使用时先发送：

> 请先阅读 README.md、docs/完整使用指南.md、.env.example 和 data/ 目录，不要创建模拟业务数据；先告诉我每个模块需要哪些真实字段，再按我的确认执行导入或修改。

每次让 CodeBuddy 修改数据前，先说明：

1. 数据来源是什么；
2. 是否包含个人信息、客户信息或平台账号信息；
3. 要写入哪个 JSON 文件或外部系统；
4. 是否需要先备份；
5. 验收标准是什么。

CodeBuddy 适合做字段整理、CSV/JSON 转换、复盘归纳和页面调整；涉及飞书写入、删除数据、外部平台采集或公开发布时，必须人工确认。

完整的 WorkBuddy 操作教程、任务提示词和界面术语表见 [docs/完整使用指南.md](docs/完整使用指南.md) 的“WorkBuddy 完整操作教程”和“工作台界面术语”章节。

## 私有数据目录

不建议把真实资料放进公开仓库。复制 `.env.example` 后设置：

```bash
WORKBENCH_DATA_DIR=/绝对路径/你的私有数据目录
WORKBENCH_OBSIDIAN_DIR=/绝对路径/你的知识库
WORKBENCH_CONTENT_ROOT=/绝对路径/你的内容资产目录
```

私有数据目录至少可以包含：

```text
dashboard-data.json
xhs-operations-library.json
experience-items.json
growth-entries.json
followup-drafts.json
meeting-notes.json
schedules.json
metrics.json
```

如果某个文件不存在，工作台会使用空结构，不会自动生成虚构记录。字段结构可参考 `data/` 中的空 JSON 文件。

## 飞书连接摘要

公开版使用飞书官方 OpenAPI 写入任务，不依赖本机 `lark-cli`。默认关闭，必须显式配置：

```bash
WORKBENCH_ENABLE_FEISHU=true
FEISHU_APP_ID=cli_xxxxxxxxx
FEISHU_APP_SECRET=xxxxxxxxx
FEISHU_BASE_TOKEN=xxxxxxxxx
FEISHU_TABLE_ID=tblxxxxxxxxx
```

不要把 `App Secret`、Base Token 或任何 `.env` 文件提交到 GitHub。完整的注册、权限、字段、测试和排错流程见 [docs/完整使用指南.md](docs/完整使用指南.md#飞书-openapi-配置)。

## 安全边界

- 默认不执行本地命令，不自动采集外部平台，不自动写入飞书。
- 前端不会接收飞书 `App Secret`；凭证只在 Node.js 服务端使用。
- 公开仓库只保留空数据结构，不保留真实账号、客户、作品、评论或公司材料。
- 真实内容发布前必须核对授权、隐私、平台规则和事实准确性。
- 启用飞书写入前，应先使用测试 Base 和测试记录验证字段映射。
